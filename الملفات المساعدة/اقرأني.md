## الخلاصة

النسخة المصححة على فرع **`release-v2`** في مستودع المشروع على GitLab.

المطلوب ثلاثة أمور بالترتيب:

1. دمج الفرع في `main` ونشره
2. نقل بيانات النظام القديم (٦٩ دورة + التوزيع الصحيح للمنسقين)
3. التحقق

---

## أولاً: لماذا هذه النسخة عاجلة

النسخة المنشورة حالياً فيها ثلاثة أعطال توقف العمل:

| العطل | الأثر |
|---|---|
| متغيّر ساقط في عناصر الإقفال | **فتح أي دورة يُظهر شاشة خطأ** — النظام غير قابل للاستخدام |
| متغيّران ساقطان في المؤشرات | الفترة المخصصة وتقرير أداء المشرفين ينهاران |
| قائمة الحقول المسموح تعديلها | **المدير لا يستطيع تغيير مشروع أي موظف ولا تعطيل حسابه** — الخادم يرد بنجاح ويتجاهل التعديل بصمت |

الثلاثة مُصلحة في `release-v2`.

## ثانياً: النشر

```bash
git fetch origin
git checkout main
git merge origin/release-v2
git push origin main
npm ci
npx prisma migrate deploy
npm run build
```

ثم النشر بالطريقة المعتمدة لديكم.

ملفا الترحيل في مجلد `ملفات الترحيل` بجانب هذا الملف. كلاهما آمن ولا يحذف بيانات — كُتبا بصيغة «أنشئ إن لم يكن موجوداً».

## ثالثاً: نقل بيانات النظام القديم

النظام القديم يحوي **٦٩ دورة** (٥٢ مقفلة، ١٧ قيد الإعداد) وسجلات الإقفال والمؤشرات والتدقيق المرتبطة بها. لم يُنقل منها شيء بعد.

### الخطوة ١ — السحب من النظام القديم

على الجهاز الموصول بقاعدة النظام القديم:

```bash
node scripts/export-legacy.js
```

ينتج مجلد `C:\nif\الملفات المساعدة\نقل البيانات` فيه ملف JSON لكل جدول، وملف `توزيع-المنسقين.json` يوضح مشروع كل منسق.

**كلمات المرور والرموز مستبعدة من التصدير.**

### الخطوة ٢ — المعاينة قبل الكتابة

على الخادم الموصول بقاعدة الجامعة، وبعد نقل المجلد إليه:

```bash
node scripts/import-legacy.js --dry
```

يعرض ما سيحدث دون كتابة أي شيء، ويُنبّه إلى أي موظف موجود في النظام القديم وغير موجود في قاعدة الجامعة.

### الخطوة ٣ — التنفيذ

```bash
node scripts/import-legacy.js
```

### كيف تعمل الأداة

- **المستخدمون**: تُطابَق بالبريد الإلكتروني، ويُحدَّث المشروع والأدوار والحالة ورقم الجوال فقط. **لا تُمسّ كلمات المرور ولا حسابات دليل الجامعة.**
- **باقي الجداول**: تُكتب بمعرّفاتها الأصلية حتى تبقى الروابط بين الدورات والموظفين وعناصر الإقفال سليمة.
- **آمنة لإعادة التشغيل**: لو شُغّلت مرتين لا تُكرّر شيئاً.

## خامساً: ميزة جديدة في قسم المشاريع

أُضيفت إمكانية **إسناد المنسقين لكل مشروع مباشرة من صفحة المشاريع**: قائمة اختيار وزر إضافة أسفل منسقي كل مشروع. إضافة منسق تنقله من مشروعه الحالي إلى المشروع المختار.

الصلاحية للمدير فقط، كما هو الحال في تغيير الأدوار.

---

## سادساً: ملاحظتان تستحقان المعالجة

**١. حاجز محاولات الدخول محسوب لكل عنوان إنترنت لا لكل مستخدم** — عشر محاولات في الدقيقة. والجامعة كلها تصدر من عنوان واحد، فقد ينقفل الدخول على الجميع في أوقات الذروة. يُنصح بتعديله ليكون لكل حساب.

**٢. التقرير القيادي** يعرض إجمالي عناصر الإقفال، لكن التصنيفات أسفله لا تشمل العناصر «غير المنطبقة»، فلا يجمع المعروض إلى الإجمالي.

## بعد النشر — يُرجى التحقق من

1. فتح أي دورة من قائمة الدورات — يجب ألا تظهر شاشة خطأ
2. صفحة المشاريع — إسناد منسق لمشروع وحفظه
3. صفحة المستخدمين — تغيير مشروع موظف وحفظه ثم تحديث الصفحة للتأكد من ثباته
4. صفحة المؤشرات — تبويب «فترة مخصصة» وتقرير أداء المشرفين
5. ظهور الدورات المنقولة بعد الاستيراد
